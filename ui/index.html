Camera capability
Only the camera id is required. A registry holds what a department has supplied and reports what it has not — a row carrying nothing but an identifier is a legitimate entry, and the gap report will name what is missing from it.
An import applies wholly or not at all. One bad row refuses the batch and names the row number and the reason, because a partial import leaves nobody able to say which half landed. Columns this registry does not know are ignored rather than refused.
The columns written here are the columns the bulk import accepts, so a department can correct a file in a spreadsheet and send it straight back.
Grades are measured from this camera's own stream and observations, not declared by the catalogue. UNKNOWN means there is not yet enough evidence to grade — it is not a poor grade.

How to use this workspace
Overview — start of shift: open alerts, how many cameras published a mark, measured store size.
Investigate — type a registration mark. Results, route and evidence open from the same search.
Alerts — watchlist hits raised by ingest, not by refreshing this page. Stolen / wanted / missing lists are ours, not a government feed.
Evidence — hash-chained records. A still is never enhanced.
Live — select a camera for moving video. Government playback uses same-origin Direct WHEP signaling, with a measured 12-session ceiling; a tile is called LIVE only after its browser player starts. Any cached image is explicitly labelled PREVIEW, never live video.
Cameras — ANPR / appearance grades measured from the stream, not claimed by the catalogue.
Analytics — distinct marks, person observations, which clocks may share a timeline.
System — hybrid of Models 1 + 2 + 3, with Model 4's central analytics on selected cameras. Model 4's statewide central recording is declined on arithmetic. Departmental VMS systems are not replaced.
Estate map — OpenStreetMap streets plus camera markers. Unlocated cameras stay in the strip; they are not invented onto the map.
Copilot — ask in sentences. I call the same read-only tools. I will not invent a plate, enhance a still, or identify a face. Person boxes are presence, not identity.
Audit log
Every entry is hash-chained to the one before it, so a removed or altered record is detectable. Records are never synthesised: if an action was not recorded, nothing appears here.

A CCTV intelligence and evidence fabric for the state camera estate. Every camera is graded by what it can actually prove, every query is attributed, and nothing is asserted that the store cannot substantiate. Proposed for the Gujarat Police Innovation Challenge 2026 — hybrid of Models 1 + 2 + 3, with selected-camera Model 4 analytics.

Sign in

Enter your Officer ID and the bearer token issued to you. The token is held in this browser tab only, for this session, and never written to disk. Both are checked against the server before the workspace opens.

The token authenticates you; the Officer ID confirms it is your token — a mismatch is refused before entry. Case and purpose are written with every query into a hash-chained audit log. A search without a stated purpose is refused.

What each role can do
  • ADMIN — registry, users, policy. Never search or read vehicle movement.
  • SUPERVISOR — statewide investigation and watchlist authority.
  • INVESTIGATOR — district-scoped investigation.
  • OPERATOR — control room: alerts and health, no search.
  • AUDITOR — reads the audit log and camera identity, never observations or evidence.
  • SERVICE — edge node sync; machine-to-machine, not an officer sign-in.
