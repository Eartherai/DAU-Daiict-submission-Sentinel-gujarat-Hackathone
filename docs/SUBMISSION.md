## Three videos

Two are required and one supports them. The two required films show what the
analytics produced — boxes and registration marks drawn on the frames they came
from. Neither shows the thing an officer actually uses, so the third drives the
real interface in a real browser against a real server and screenshots each
step. Nothing is mocked and no screen is staged: every frame is Chrome
displaying the served page, and if a panel is empty there it is empty in the
product.

The walkthrough follows the work in the order it happens — Overview, purpose
binding, Find, Trace, Cameras, Analytics, Live, Alerts, the case file, Evidence,
Audit. The recorder reports any step it could not drive rather than skipping it
silently, and all eleven drove.

The narrated launch film adds an Indian-English voiceover (system offline
text-to-speech, voice Aman — en-IN; no cloud service touches it). Each
segment's audio is padded to exactly its on-screen duration and concatenated in
order, so the voice stays in sync with the screen by construction, not by a
timing guess. On a host without `say`, the tool refuses rather than shipping a
silent file that looks narrated.

## The two required videos, and why there are two

Both run the same detector, tracker and ANPR. There is no demonstration path in
this code, no per-camera special case and no replay of saved detections: if a
video shows a box, the detector produced it during that run. Each report is
written from the same rows that were drawn on the frames, so a report and its
video cannot disagree.

They differ in one respect, stated on every frame of both:

**Government grid** — 6 of 6 cameras opened, **343 vehicles tracked, 6,625
timestamped rows**, analysis at a mean of 4.5 frames per second of stream time.
**Zero registration marks read.**

**Local synthetic corpus** — 6 clips, **32 vehicles, 12 distinct registration
marks**, two of them (`GJ01CD5678`, `GJ35BV6925`) read on **two different
cameras**.

That contrast is the finding, not an embarrassment. ANPR is not weak: plate
width at the government estate's mountings is well below what any reader needs,
and the platform grades each camera for exactly this and says which cameras can
carry a registration claim. The corpus is used *because* its marks are known in
advance — a read there can be scored right or wrong, which is impossible on real
footage where nobody can say what the correct answer was.

Provenance is stamped on every frame of both videos, and the field has no safe
default: it reads `PROVENANCE NOT STATED` unless a caller sets it.

## Reproducing all of it

```bash
python tools/demo/record_walkthrough.py --port 8003 --token <short-lived token>
python tools/demo/render_deck.py
python tools/demo/render_diagrams.py
python tools/demo/render_demo_video.py --media var/media --seconds 24 --out var/demo/own_feed
python tools/demo/render_demo_video.py --db sqlite:///var/live.db --seconds 30 --out var/demo/government_feed
```

The government run needs credentials for the organiser's grid in the
environment. They are never written to the repository, the logs, the console or
the frames: stream URLs are redacted at every exit from the renderer.

## The live grid, as of this submission

The grid now **authenticates every stream connection** with a registered email
and access password embedded in the URL authority — this is stated in the
integrator's guide. Our stored URLs carried no credential, which is why every
connection was refused with 401; the earlier note that access had been "revoked"
was wrong, and is corrected in CR-036. With the credential supplied through
`SENTINEL_GRID_EMAIL` and `SENTINEL_GRID_PASSWORD` (environment only, in no file
in this repository), the live wall streams real cameras: `cam01` opens
1920×1080 h264 in 2.5 s, and the walkthrough on the live grid shows four
Sentinel cameras at once.

The credential is injected in the moment before the socket opens and redacted at
every exit that can quote a URL, so it never reaches a log, an export, a
database row or a screenshot. Eight tests in
`tests/security/test_grid_credentials.py` pin that containment.

The live store as of 6 September 2026 10:54 UTC holds **552,889
observations** from all 30 cameras, including **145,868 persons**
(`docs/MEASURED_RESULTS.md`). The generated sheet holds **44 distinct
registration marks**: **70** corroborated (votes ≥ 2) and **17 leads**
(votes = 1); **none** repeats across cameras. Forensic OCR attempts
(`plate_reads`) **737**. Eight cameras published a mark. A one-frame plate is published as a lead labelled
`REQUIRES_VERIFICATION` (CR-040). Search names a looping single-camera
pattern `SINGLE_CAMERA` rather than a fleet (CR-050).

### Accessibility

The interface is built to **GIGW 3.0 and WCAG 2.2** — the standard Indian
government software is audited against — with landmarks, a skip link, an `h1`
outline, `:focus-visible` indicators at contrast on both the navy chrome and the
light workspace, `aria-live` regions on everything that changes, reduced-motion
and forced-colors handling, and an operator density control (comfortable / large
/ wall) for reading the same screen at a console and across a control room. See
CR-037.
